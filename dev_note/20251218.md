# My Diary Backend 개발 노트

### Django 기반 다이어리 서비스 – 리셋 & 복구 기록

---

## 1. 개요

본 프로젝트는 Django + Django REST Framework 기반의 개인 다이어리 서비스 **My Diary**의 백엔드 개발 과정에서 발생한 구조적 오류와 환경 문제를 해결하고,
**두 차례의 전면 리셋을 통해 안정적인 베이스라인을 재구축한 기록**이다.

단순한 버그 수정이 아니라,

> **“왜 꼬였는지 → 무엇이 잘못됐는지 → 어떻게 다시 세웠는지”**
> 를 명확히 이해하고 정리하는 것을 목표로 한다.

---

## 2. 1차 문제 발생 – 프로젝트 구조 붕괴

### 1) 초기 증상

* `/api/` 및 `/api/dailylogs/` 접근 시 404
* admin 페이지는 정상 동작
* `DailyLogViewSet`, `DailyLogSerializer` import 에러 반복 발생
* `RuntimeError: Model class diary.models.DailyLog doesn't declare an explicit app_label`
* 마이그레이션이 생성되지 않거나, 생성되어도 적용되지 않음

---

###  원인 분석 (1차)

#### 1️) Django 버전 문제

* Django **6.0** 환경에서 프로젝트가 생성됨
* Django REST Framework 및 기존 프로젝트 구조와의 **호환성 문제 발생**
* 공식 문서 및 DRF 안정 버전 기준과 불일치

#### 2️) 앱 인식 실패

* `INSTALLED_APPS`에 `diary`가 **있어 보이지만 실제로는 로딩되지 않음**
* `apps.get_app_configs()` 결과에 `diary`가 없음
* → Django가 해당 앱을 “존재하지 않는 앱”으로 취급

#### 3️) 설정/파일 누락

* `corsheaders` 라이브러리 미설치
* serializers / views / urls 일부 파일이 리셋 과정에서 누락
* admin 등록 중복 (`AlreadyRegistered` 에러)

---

## 3. 1차 해결 시도 → 실패 판단

###  시도한 해결 방법

* import 경로 수정
* app_label 수동 지정 시도
* urls / views / serializers 재작성
* migration 재생성 시도
* DB 초기화 시도

###  결론

> **코드 문제가 아니라 “프로젝트 베이스 자체가 망가진 상태”**

부분 수정보다 **전면 리셋이 더 빠르고 안전**하다고 판단.


## 6. 정상 구축 단계 (성공 루트)

### 1️) Django 프로젝트 생성

```bash
django-admin startproject config .
```

### 2️) diary 앱 생성

```bash
python manage.py startapp diary
```

### 3️) settings.py 등록

```python
INSTALLED_APPS = [
    ...
    'rest_framework',
    'diary.apps.DiaryConfig',
]
```

### 4️) DailyLog 모델 작성

* 날짜, 기분, 메모, AI 요약 필드 포함

### 5️) 마이그레이션

```bash
python manage.py makemigrations diary
python manage.py migrate
```

### 6️) admin 등록

* 중복 없이 1회만 등록

### 7️) serializers / views / urls 작성

* `ModelViewSet` + `DefaultRouter` 사용

### 8️) 서버 실행

```bash
python manage.py runserver
```
